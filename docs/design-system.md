# Class Log 디자인·UX 원칙

이 문서는 현재 Class Log에서 지켜야 할 **최소 UI/UX 불변조건**을 정리한다.

아직 브랜드 컬러·타이포그래피 전체를 새로 정의하는 단계가 아니므로, 저장소에 이미 존재하는 UI 패턴을 우선 재사용한다.

---

# 1. 기본 원칙

1. 기존 화면 스타일과 컴포넌트 패턴을 우선 재사용한다.
2. 데이터모델 변경을 이유로 전체 UI를 재디자인하지 않는다.
3. 사용자가 저장됐다고 착각할 수 있는 버튼명/상태를 피한다.
4. 입력 도중에는 불필요한 오류를 남발하지 않는다.
5. DB 용어보다 운영자가 이해하는 한국어 라벨을 우선한다.
6. Draft·확정·중단·비활성처럼 의미가 다른 상태는 시각적으로 구분한다.
7. destructive action은 결과가 명확해야 한다.

---

# 2. DB 값과 UI 라벨

## 프로그램

| DB | UI |
|---|---|
| `weekday_vocal` | 평일보컬 |
| `weekend_vocal` | 주말보컬 |
| `rental` | 대여 |

## 프로그램 저장 상태

| DB | UI |
|---|---|

| `stopped` | 중단 |

`inactive`는 계산 결과이며 UI에서는 `비활성`으로 표시한다.

|---|---|
| `break` | 잠시 쉼 |

| `other` | 기타 |

# 3. 상태 표시

## Draft

Draft는 학생에게 보이지 않는다.

운영자 일정에서는 일반 일정과 혼동하지 않도록 명확한 `임시`/`Draft` 표시를 사용한다.

Draft를 확정할 때는 상태가 바뀌는 것을 사용자가 이해할 수 있는 버튼명을 사용한다.

예:

- `임시 저장`
- `일정 확정`

## 프로그램 비활성

비활성은 운영자가 직접 바꾸는 토글처럼 보이면 안 된다.

시스템이 계산한 상태라는 점을 필요하면 보조 설명으로 보여준다.

---

# 4. 날짜·시간 직접 입력 UX

기존에 해결한 날짜/시간 dropdown과 direct input 동기화 동작을 깨뜨리지 않는다.

## 한 자리 입력

월/일 등에 `1`처럼 한 자리 숫자를 입력하는 순간부터 형식 오류를 띄우지 않는다.

사용자가 Tab/blur로 필드를 떠날 때 유효한 한 자리 값이면:

- `1` → `01`
- `9` → `09`

형태로 정규화한다.

## 두 자리 입력

`12`처럼 유효한 두 자리 값이 완성되면 기존 자동 이동 UX를 유지한다.

## 실제 invalid 값

표준 범위를 벗어난 값은 오류를 표시한다.

예:

- 13월

즉, **아직 입력 중인 값**과 **완성됐지만 잘못된 값**을 구분한다.

---

# 5. 오류 메시지

오류는 사용자가 무엇을 고쳐야 하는지 알 수 있게 작성한다.

좋은 예:

- `진솔 학생은 8월 30일 19:00 일정과 시간이 겹칩니다.`
- `평일보컬이 중단된 학생은 새 일정에 배정할 수 없습니다.`

피해야 할 예:

- `Invalid assignment`
- `Constraint failed`

DB 오류 원문을 그대로 사용자에게 보여주지 않는다.

---

# 6. 학생 프로그램 UI

학생 상세에서 다음을 한눈에 구분할 수 있어야 한다.

- 현재 프로그램
- 진행중/중단/비활성
- 시작일
- 중단된 경우 종료일
- 선택적 중단 사유

과거 프로그램 이력은 현재 프로그램과 구분한다.

---

# 7. 보강 UI

기본 탭/상태:

- 보강 대기
- 보강 예정
- 완료

보강 대기 항목의 핵심 CTA는 `일정 배정`.

배정 시:

- 기존 일정 선택
- 새 일정 만들기

두 경로를 구분한다.

---

# 8. 피드백 UI

피드백과 댓글을 한 UI 개념으로 합치지 않는다.

- 피드백: 공식 기록
- 댓글/답글: 이후 대화

피드백 작성 시 실제 제공 직원과 입력자가 다를 수 있다는 점을 UI에서 처리한다.

---

# 9. 직원 UI

직원 정보와 로그인 계정을 같은 의미처럼 표시하지 않는다.

로그인 계정이 없는 보컬트레이너도 담당자로 선택 가능해야 한다.

---

# 10. 아직 확정하지 않은 것

다음은 현재 문서에서 새로 결정하지 않는다.

- 전체 브랜드 컬러 재설계
- 새 타이포그래피 시스템
- 다크모드
- 대여 예약 화면
- 학생 계정 관리 전용 화면
- activity type UI

필요해질 때 실제 저장소 UI와 제품 요구를 보고 별도 결정한다.

---

# 저장 성공 피드백

사용자가 명시적으로 저장 버튼을 누른 관리 화면은 성공 여부를 분명히 보여준다.

예:
- `담당직원이 저장되었습니다.`

DB mutation이 실제로 성공하지 않았는데 성공 메시지를 보여주면 안 된다.

# 로그인 진입 화면

운영자 로그인/학생 로그인처럼 역할 선택 후 들어온 페이지에는 이전 선택 화면으로 돌아갈 수 있는 뒤로가기 UI를 후속으로 추가한다.
